# Bar Badge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace galley's inline bar count (`󰐪 3`) with a notification-style badge — a small accent-filled circle overlaid on the glyph's top-right corner.

**Architecture:** Two layers, matching the repo's existing split. `Model.js` gains one pure function, `badgeText(snapshot)`, that turns a snapshot into the string the badge shows (`""`, `"1"`…`"9"`, or `"9+"`); it is unit-tested under `node --test`. `Panel.qml` drops the count from its `WidgetButton.text` and declares a `BorderSurface` child that renders that string, anchored to the glyph via the button's existing `labelWidth` property. No new files, no new imports, no new cross-language invariants.

**Tech Stack:** QML (Quickshell / omarchy-shell), ES5-subset JavaScript, `node --test` for the JS suite, `bin/test` as the umbrella runner.

**Spec:** `docs/superpowers/specs/2026-08-09-bar-badge-design.md` (commit `ef5e09c`)

## Global Constraints

- **`Model.js` stays pure and QML-safe.** It is loaded by both `Panel.qml` and `node --test`, and the two engines do not support the same syntax. Everything at the top level must be `var` or `function` declarations only. Do **not** introduce: arrow functions, spread (`...`), template literals, `let`/`const`, `Object.assign`, `.includes(`, or `.endsWith(`. (`tests/model.test.js` is exempt — it only runs under node, which is why modern JS appears there and nowhere in `Model.js`.)
- **`Model.js` performs no I/O, has no QML imports, and holds no state between calls.**
- **The bar slot width stays `Style.space(27)`.** Shrinking it shifts every widget to galley's right. Do not change `fixedWidth`/`fixedHeight` on the `WidgetButton`.
- **The badge carries no severity.** `Model.barSeverity` keeps tinting the glyph red/amber; the badge fill stays `Color.accent` in every state.
- **The badge accepts no mouse events.** It must not contain a `MouseArea`, or it will swallow the button's click-to-open, middle-click-to-refresh, and tooltip.
- **The count stays `summary.activeJobs`.** This change is presentation-only.
- **`BADGE_MAX` is `9`** and never leaves JavaScript — it must not be duplicated into Python, QML, or `manifest.json`.
- Run the full suite with `bin/test` from the repo root. Python is stdlib `unittest` (no pytest on the mise-managed `python3`).

### Task 1: `Model.badgeText`

The pure function that decides what the badge says. Hidden-at-zero is encoded as
the empty string, so `Panel.qml` needs no second predicate for visibility.

**Files:**
- Modify: `Model.js` — add `BADGE_MAX` beside the other top-level constants (near `COLOR_BUSY`, line 7), add `badgeText` after `barSeverity` (line 153-165), add to the `module.exports` block (line 288-305)
- Test: `tests/model.test.js` — add cases after the existing `barSeverity` block (ends line 130)

**Interfaces:**
- Consumes: nothing from earlier tasks.
- Produces: `Model.badgeText(snapshot)` → `string`. Returns `""` when there are no jobs or the snapshot is unusable; the decimal count as a string for 1–9; `"9+"` for 10 or more. Task 2 binds a QML `Text.text` directly to its return value and treats `""` as "hide the badge".

```javascript
// Past this, the badge shows "9+" rather than the true figure. Keeping the
// badge a fixed-width circle is the point: a two-digit count would widen it
// into a pill that overhangs the bar slot and crowds the next widget. The
// exact figure stays available in the tooltip.
var BADGE_MAX = 9
```

- [ ] **Step 4: Add the function**

In `Model.js`, immediately after `barSeverity` closes (after line 165, before `function plural`), add:

```javascript
function badgeText(snapshot) {
  var summary = (snapshot && snapshot.summary) || {}
  var count = summary.activeJobs || 0
  // "" doubles as the visibility flag. An idle queue is the common case, and
  // this saves Panel.qml a second call to ask whether to draw at all.
  if (count <= 0) return ""
  return count > BADGE_MAX ? BADGE_MAX + "+" : String(count)
}
```

- [ ] **Step 2: Add the badge as a child of the button**

Inside the same `WidgetButton { ... }` block, after the closing brace of
`onPressed` and before the block's own closing brace, add:

```qml
    // Declared inside the button so it paints above the button's own label,
    // and so it can anchor to the painted glyph rather than to the slot.
    // No MouseArea here on purpose: a bare Rectangle/Text consumes no mouse
    // events, so click-to-open, middle-click-refresh, and the tooltip all
    // keep working straight through the badge.
    BorderSurface {
      id: badge
      visible: badgeLabel.text !== ""
      width: Math.max(9, button.fontSize * 0.85)
      height: width
      radius: width / 2
      color: Color.accent
      // The 1px ring in the bar's own background is what separates the badge
      // from the glyph underneath; without it the two shapes smear together.
      borderSpec: Border.flat(Color.bar.background, 1)

      // WidgetButton centers its label, and exposes labelWidth precisely so
      // bar chrome can line up with the painted text instead of the slot.
      // Half the label width right of center is the glyph's right edge; half
      // a font-size above center is its top. The badge straddles that corner.
      anchors.horizontalCenter: parent.horizontalCenter
      anchors.horizontalCenterOffset: button.labelWidth / 2
      anchors.verticalCenter: parent.verticalCenter
      anchors.verticalCenterOffset: -button.fontSize * 0.5

      Text {
        id: badgeLabel
        anchors.centerIn: parent
        text: Model.badgeText(root.statusSnapshot())
        color: Color.background
        font.family: root.fontFamily
        font.bold: true
        // 0.66, not the 0.72 TailscaleIcon.qml uses — that was tuned for a
        // single "!", and "9+" is two characters.
        font.pixelSize: Math.max(6, parent.height * 0.66)
      }
    }
```

Three notes for the implementer:

- **`statusSnapshot()`, not `snapshot`.** This matches the two neighbouring call sites (`foreground` and `tooltipText`). It is not a behaviour change: `statusSnapshot()` overrides only `cupsd` and `error`, and `badgeText` reads neither.
- **Sizing off `button.fontSize`, not `button.height`.** The spec sketched `button.height * 0.42`; `fontSize` is used instead because it gives the same result on a horizontal bar while also working on a vertical one, where the button's height is `Style.space(26)` rather than the bar size. Both orientations center the label and leave `textRotation` at 0, so this single anchoring covers both and the spec's separate vertical-bar branch is not needed.
- **No import changes.** `Panel.qml` already imports `qs.Ui` (`BorderSurface`) and `qs.Commons` (`Color`, `Border`, `Style`).

- Widgets to galley's right have **not** shifted position.

## Notes for the implementer

**A discrepancy you will see, and must not fix here.** While cupsd is asleep, the badge keeps showing retained job counts, but `tooltipText` returns "CUPS idle, nothing queued". The badge and the tooltip disagree. This is pre-existing — the inline count behaved identically — and is logged in `docs/FOLLOWUPS.md` under known behavioural choices. The spec calls it out and scopes it out. Fixing it is a separate decision about `tooltipText`.

**Dead code you will notice, and must not touch.** `printerGlyph(state)` in `Model.js` is exported with no caller, and returns a stale pre-`c5f83a1` glyph. `AGENTS.md` flags it as a deliberate open question, not an oversight. Leave it.

**No cross-language guard is needed.** `tests/test_cross_language.py` exists to catch values hand-duplicated across Python/JS/QML. This change adds none: `BADGE_MAX` lives only in `Model.js`, and `Color.accent` is resolved by the shell's theme rather than copied into galley.
